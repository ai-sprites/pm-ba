# 需求与用户故事

使用本 Skill 完成 PM / BA 的实际工作。先读[工作流](references/workflow.md)，再读取本次需要的完整模板；不要求其他角色已安装。

| 工作 | 读取模板 | 实际产物 |
| --- | --- | --- |
| 新产品、完整功能的需求整理或评审交接 | [PRD](assets/templates/prd.md) | 创建或更新业务项目的 PRD |
| 可独立交付、验收或需要详细流程的用户任务 | [用户故事](assets/templates/story.md) | 创建或更新故事，PRD 链接到它；已有内嵌故事可沿用同等结构 |
| 已有需求的局部迭代 | 对应 PRD / 故事模板作为核对依据 | 只更新受影响的规则、流程和验收，保留原编号与其余内容 |

模板必须读取后按真实需求填写，不能用摘要替代模板、把空模板当成果，或把示例当用户决定。正文用白话，保留章节和字段的专业含义；使用本次适用的表格，不为缺少依据的信息凑答案。不适用章节可简短说明原因，不要求人逐项填表。

新产品或完整功能交接默认实际保存 PRD，不等用户催问产出。故事采用“作为〈用户〉，我希望〈能力〉，以便〈价值〉”或等价格式；故事与每条验收保留稳定编号，验收写清前置条件、动作、可观察结果。验收正文只维护一处，PRD 与故事以真实链接关联。

沿用用户指定的业务仓库，本角色新增或更新的需求、故事、验收和附件统一放在仓库根目录下的 `docs/pm-ba/`，例如 `docs/pm-ba/prd.md`、`docs/pm-ba/stories/<故事编号>-<名称>.md`；多个功能可在角色目录内分子目录。本次涉及的旧散落产物先迁入该目录，保留内容、自定义和手写修改，同步文档链接、已有索引和消费引用；目标存在同名文件时先比对合并，不能覆盖用户内容。资料读取不限制来源位置，正常代码与测试留在原处，业务产物不放进角色或 Skill 安装目录。无写入能力时给完整正文并说明未落盘。交付实际文件链接、已完成内容和必须决定的具体问题；“继续/有什么产物”不授权设计、原型、API、技术选型或应用实现。

接入时沿用已明确的资料 host repo 和产物 repo；缺项合并用白话问一次，允许稍后配置。必要决定在可用提问界面或对话中直接问，说明选项与影响，收到答案再做依赖部分并写回；已有答案和授权不重问，其余工作继续。

本地资料直接读。跨 Git 读取、固定版本或导出确有需要时，复用或按 [artifact-bridge 手册](https://github.com/ai-sprites/artifact-bridge)补齐同一明确版本的完整 Skill。bridge 原始导出整包（含 `manifest.json`）放在 `docs/artifact-bridge/`，本角色加工成果及附件放在 `docs/pm-ba/`。PRD、独立故事和必要附件各自给出真实仓库根相对路径；只有进入可获取提交的文件才能跨 Git 读取。已有索引随文档创建、更新、移动、删除同步，保留其他条目；bridge 不替上游写入或推送。
